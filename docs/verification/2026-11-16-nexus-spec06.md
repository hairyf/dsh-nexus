## 装配与根因修复

[宿主说明](../../src/host/README.md) 记录了资源归属和已核实底座接口。

1. 一个 await 的 ctx.effect 生命周期，迁移成功后才注册入口并激活调度、GitHub、提醒和角色恢复。appReady 后建立责任，显式 inject timer；初始化、失联、投递失败与真实空闲可区分。
2. 27 个原型抛错工具由可信工厂接上真实账本/runtime/channel。只在 Nexus 根会话的可信 create/resume setup 安装，不凭 preset 名给 helper/侧聊身份。
3. 安装前逐 agent 捕获原生 send_message。agent_id 走原实现与原上下文，保留原生 messageId，不破坏原生父子代理通信。
4. 回执只在真实持久 user/message 才标 read。成功 handoff 到 inbox claim 的瞬时窗口用进程内 accepted 集合保留 queued，不把短暂离开 inbox 当 absent，避免取消/补投自激；该集合不是逐消息 claim 证明。
5. 原生 cold resume 不自动唤醒旧 inbox：仅确有 Nexus 输入时，以公开 remove/send 重排原队尾，保持原 MessageId、source、目标与顺序，不造恢复 prompt。精确相位有接口回归测试，未谎称全部真实故障注入已覆盖。
6. 人 resume 通知原 project 责任，不靠别票事件偶然唤醒。正式答案不解除人工暂停；结束先验证交付事实，再独立退役写入者，缺证据不假标关闭。
7. Native owner 目标通过互斥 sourceMessageId 开票：宿主读取当前绑定 main 的真实最新用户消息、非空 RPC 标识、缺席的 non-owner principal，并校验内核消息 ID；不信 actor/human/verified 参数。RPC 标识本身不是权限凭证，信任锚是既有连接层/gateway 契约。来源与票在同一事务提交，失败无半张票；原 GitHub 同仓库限制及其他角色建票限制未放宽。
8. 侧聊使用原生既有席位，先同步打开原会话再挂已有 sidebar。客户端类型不能成为运行时 require。没有额外演示后端或假数据。
9. GitHub 只读 preflight 核实账号、真实 base/head、仓库要求和检查；真正合并仍消费正式决定。空 answer_result 不渲染为拒答，防止自发托管评论进入无穷 PATCH 回路。
