# 05 Web 编排面板与信箱

状态：用户已批准（2026-11-16）。日期：2026-11-16。

总纲：[dsh-nexus 一期总纲](./11-16-nexus-v1-master-design.md)。依赖 [01 账本与策略](./11-16-nexus-v1-ledger-policy-design.md)、[02 运行编排](./11-16-nexus-v1-runtime-design.md)、[03 统一问答](./11-16-nexus-v1-communication-design.md)。GitHub 运行连接可由 04 并行提供；本模块不另维护外部状态。

## 目标与非目标

让用户查看目标和进展、处理少量待决问题、核验交付，而非维护大量会话。复用当前 Nexus 面板、组件和宿主主题，将示例数据替换为真实读模型，不另建独立应用、主题或泛化可视化平台。

一期不接 deep-view、不做侧聊只读隔离、不增加侧聊权限系统/同步协议，不把内部工具日志变成默认管理首页。

## 页面责任与访问任务

| 用户任务 | 页面优先内容 | 不应成为操作前提 |
| --- | --- | --- |
| 我现在要决定什么 | 需要本人回答的 ask、到期提醒、真实需人阻塞 | 阅读所有代理收件箱 |
| 目标推进到哪里 | 项目/工单目标、状态、依赖、阻塞原因、负责人 | 逐个打开会话 |
| 能否认可交付 | 验收要求、产物、PR/CI 事实、有效决定与证据 | 从聊天散文猜是否已完成 |
| 调整自动化范围 | 可用项目启用范围、全局默认、白名单、工单实际配置 | 手写凭证 shim 或修改数据库 |
| 追问背景 | 原会话近况与现有侧边对话入口 | 打断工作会话重新问一次 |

总览保留现有编排图并接真实关系，展示 main、项目、临时 supervisor、工单/执行的层级与依赖；可按项目/状态聚焦。图不是另一套账本，也不要求用户手工维护连线。日志、事件明细、原始会话保留按需入口。

## 信箱与 ask 卡

- 默认只汇总需用户回答/处理的事项，不把所有上级代理 pending 当成用户未读。显示谁在等、工单和来源、问题、选项、需要什么决定、等待时长与提醒状态。
- 展示来源会话最近的有效上下文，并注明来源与时间；可按需读取更多。不得为每张卡无界重放全部历史，也不将模型摘要冒充原始事实。
- 原始工作会话不可用时显示可用的已记录问题/近况及失败原因，仍能回答持久问题，不能用空白卡掩盖错误。
- 合并卡显示具体 PR、目标分支、head 与验收/检查依据；目标变化后旧按钮不能继续批准新代码。必须人答的卡不显示代理默认同意或倒计时自动批准。
- 正式答复使用 askId，经宿主身份和 03 统一语义结清；提交中防重复，失败保留输入，冲突显示已有答案而非覆盖。
- GitHub 已回答时，Web 撤下可操作控件并显示实际回答来源；Web 已回答后，GitHub 同步失败作为同步问题显示，不要求用户再答。
- 提醒关联原 ask，更新等待时长/醒目标记及已有入口；不复制一个新的待答卡或悄悄改变问题责任。

用户信箱与角色详情可看到“投递失败”“待处理”“已入上下文”“等人”的区别；不能把工具已受理渲染成已完成，也不能用一个 spinner 表示所有长期状态。

## 侧边对话直接复用

ask 卡提供打开对应来源会话侧边对话的入口，沿用 DSH-better-sidebar 已有的上下文、权限、工具与对话行为。这里不追加只读模式、专用 preset、人工介入同步协议或新的批准机制。

若公开插件接口缺少“从该来源会话打开侧聊”的最小能力，可做最小接线/API 扩展：本地改好验证后，统一向对应上游提 PR。只开放既有行为所需入口，不借此扩充权限控制体系；保留无改动可复用部分。

来源明确时必须打开来源会话，不能误用当前面板焦点会话。打开失败给出原因和打开原会话的恢复路径，不默默新建无关对话。现有侧聊并不自动把回答送回原工作会话，也不因此结清 Nexus ask。

依据：[DSH-better-sidebar](https://github.com/dsh-external/DSH-better-sidebar)。沿用现有语义，不将调研中提出但未获用户采纳的只读/gate 设想写成一期要求。

## 工单、项目与配置

- 工单详情显示目标、验收要求、来源话题、执行历史、依赖、产物、PR/CI 当前事实、ask、暂停与故障原因；成功/取消/未合并关闭不可混同。
- 工单展示 questionLevel 与 mergePolicy 的实际快照，可由有权用户单独修改；编辑全局默认明确提示只影响新工单。
- 项目列表由可用 Git 工作区发现并保留启用选择；不可用/失联历史不删除，不刷新后默认全选，不给非 Git 或无 remote 工作区派工。
- 全局设置承载 01 的默认档位、合并策略、白名单和运行参数，不新增按仓库角色推导授权、每项目 Bot 或多对多配置。
- GitHub 使用 04 约定的 gh 环境与状态；真实能力未连通时不以示例“已连接”或不可用按钮假装完成，也不另外开发 OAuth 系统。
- 暂停/继续、取消、重试等操作通过 02 管理语义，有明确作用范围及结果；不把普通留言当作恢复被人暂停的授权。

## Host 边界与状态来源

本模块拥有 Web 的查询/操作入口和客户端交互契约，遵循项目现有路由/服务规范；业务判断调用 01/02/03，不在组件里复制策略。请求归属与身份在宿主入口核验，不能接受前端自报的 actor 作为授权。

查询可组合项目/工单、用户信箱、会话近况和外部投递事实，但不得产生平行真源。更新/重连后以服务端状态对账，避免本地留着已经被另一端回答的卡。来源链接、GitHub 发布关联由账本提供，不从工单显示名猜 URL。

沿用现有 DSH main/sidebar 插件席位和宿主 API；不新增替代当前 GUI 的服务器。是否自动热更新取决于实际 watcher 和产物，不能仅因为源码已改就承诺当前页面已更新。

## 交互与错误语义

- 使用宿主主题令牌与现有密度，不引入独立 tokens/theme。优先显示行动和后果，诊断细节按需展开。
- 待答/进行中/已解决/暂停/错误/空态明确；真空、筛选为空、读取失败各有合适动作，不能统一成“暂无数据”。
- 键盘可进入卡片、选项与侧聊入口；非鼠标用户能完成答复。提交反馈、焦点归还、错误输入保留，不用 hover-only 入口承载唯一功能。
- 读取或保存失败显示“什么失败、为什么、如何恢复”；响应较慢有就地反馈，不用持续 spinner 隐藏真实等待对象。
- 尚未受理的提交不能显示成功；已受理但待外部同步有单独提示。消息发送失败不能隐式改投另一个公开话题。
- 一张 ask 从多入口竞争提交时，以 03 的已生效答案为准，UI 不自行仲裁或回滚服务端决定。

## 独立验收与测试范围

- 总览、工单、图、信箱、渠道和设置使用真实查询结果，不从示例常量伪造运行状态；同一事实不同视图一致。
- 全局修改不动已有票快照；项目刷新保留选择，失联/禁用不自动派工；暂停后的源事件不把 UI 显示成自动恢复。
- 正常题目、选项/多选、必要人答、跨端已答、同步失败、来源不可用、长等待提醒与错误恢复均有可验证交互。
- 实际打开正确来源的既有 sidechat，保留其原有行为；不注册成另一个工单 Worker，不让侧聊关闭原 ask。
- 深浅主题、键盘完整路径、输入保留、窄屏和重连对账；不以截图或静态源码字符串代替交互断言。
- 组件/Host 测试可隔离外部渠道，但不能用假后端声称端到端已通过；真实浏览器与既有 GUI 验收由 06 统一记录。

## 后续方向：deep-view（不属于一期）

[deep-view](https://github.com/Fei2411/deep-view)可作为后续 Web 交互视图候选，其他渠道提供文本/链接降级。它当前不是 Nexus ask 的答案系统，不能直接代替批准与持久问答。

本期只记录这一方向，不安装、不接入、不修改其协议，也不把向该仓库提 PR 作为一期完成条件。以后是否采用、怎样与普通用户消息交互，再独立设计。
