# 06 宿主装配与真实验收

状态：用户已批准（2026-11-16）。日期：2026-11-16。

总纲：[dsh-nexus 一期总纲](./11-16-nexus-v1-master-design.md)。依赖 [01](./11-16-nexus-v1-ledger-policy-design.md)、[02](./11-16-nexus-v1-runtime-design.md)、[03](./11-16-nexus-v1-communication-design.md)、[04](./11-16-nexus-v1-github-design.md)、[05](./11-16-nexus-v1-web-design.md)。本 Spec 拥有最终宿主装配、跨模块验证与完成证据，不重复定义领域权限或工具协议。

## 目标与边界

证明一期是可运行的目标—工单—执行—问题—验收闭环，而不是工具 schema、数据库或页面样例的组合。各模块先完成局部验收，此处验证边界真正接通，并保证启动、卸载、恢复与测试隔离一致。

本 Spec 可完善集成入口和测试设施；不借测试改写其他子 Spec 的政策，不安装 deep-view，不接其他渠道，不要求升级 DSH，不建立第二套演示后端。

## 宿主装配责任

- 数据/迁移成功后再激活项目发现、消息处理、调度、GitHub 收发与提醒。初始化失败可见，不让空状态或部分启用冒充成功。
- 角色绑定、领域工具、会话事件、渠道输入输出与 Web 路由都进入同一 profile 的账本；不能仍有未被调用的数据库或只抛“尚未实现”的关键路径。
- 以插件生命周期管理监听、调度和资源。热重载/重新启用不重复注册工具或建立两个 dispatcher；卸载停止继续派发，持久待办保留。
- 正常启动能恢复 main/project/supervisor/worker 责任与 pending ask，不依赖用户手动打开每个会话。只继承 preset 的 native helper/sidechat 不被误挂工单角色。
- Web 使用当前宿主既有席位/API；GitHub 使用已选 gh 环境；不启动一个替代 GUI 来冒充现有页面已更新。
- 不把外部缺配置/凭证、模块初始化失败、投递失败及真实空闲混成一个状态。无法运行就明确报阻塞，不放假成功数据。

## 模型与测试环境

所有实际智能体行为测试使用 **DeepSeek Flash + max 思考**。测试配置须记录解析后的 provider、model、reasoning 设置及 DSH/插件版本，不能用另一个模型跑通后只改显示名称。测试代码和独立审查者的模型不代表被测执行模型。

依赖真实 DSH CLI 与 Playwright Chromium。现有 [Vitest 配置](../../../vitest.config.ts)及[浏览器项目](../../../vitest.e2e.config.ts)是测试入口，不另建一套 Playwright 测试框架。

目前 [shell smoke](../../../test/e2e/smoke.spec.ts)只证明壳能打开；[现有启动准备](../../../test/__setup__/shell.ts)把 profile 放在真实 home，且 CI 可回退 web。独立 profile 名称不等于隔离 home，此处必须消除此风险：

- 自动化测试的 DSH home、profile、Nexus 库、会话、worktree 与产物都落在专用临时环境，禁止回退写真实用户 web profile。
- 若提供 DSH_E2E_HOME 等测试入口，须真正映射到底层受支持的 home/profile/state 路径并验证实际落点；不能仅设置无效的 DSH_HOME 环境变量便声称隔离。
- 不复制真实凭证进夹具或日志；使用显式选择的测试凭据/已有受控凭据入口。缺模型或 GitHub 凭据时阻塞真实验收并说明需要什么，不能条件跳过后报告全绿。
- 模块测试允许隔离第三方边界；端到端验证必须使用真实 Nexus 后端、DSH、浏览器和模型，不能 mock 被测系统或用写库造状态代替完整链路。
- 本地与 CI 使用同一身份、问题、完成判据；等待用状态/事件及有界断言，不用固定长睡眠赌时序。

## GitHub 实测范围与外部副作用

用户指定真实测试仓库为 [omdsh-dev/dsh-nexus](https://github.com/omdsh-dev/dsh-nexus)。真实工单/PR 使用清晰 run 标识，测试记录可关联到本次运行，不改写现有用户话题。

- 允许测试 issue、PR 和评论，不代表获准改 main/dev。真实合并必须指向本次创建的隔离测试 base 分支，Worker 分支也隔离；正常项目的目标分支不被测试设置覆盖。
- 测试实例应能明确指定这一目标 base，并让批准、验收和合并都核对同一个 base/head。不能以真实默认分支作为方便的测试目标。
- 测试客户端可模拟有权用户在 Web/GitHub 正式回答，报告须说明这是受控测试输入，不谎称真实用户已逐项人工操作。
- 用真实账号与白名单配置变化验证准入、非白名单拒绝和 Nexus 自己的出站消息不构成人批；不要求临时伪造另一个 GitHub 账号或绕过身份核验。
- 跨项目测试可采用一个可写测试项目与一个明确只读的独立仓库项目：两个真实 Git 工作区和 DSH 执行，由 supervisor 协调，另一项目交付调查成果即可。不为证明跨项目而擅自在第二个远端仓库建 PR。
- 同一逻辑话题原位更新，不靠重复评论制造提醒；结清测试 issue/PR、清理本次产生的隔离引用并保留证据链接。只操作已经核实属于本 run 的资源，不删除用户内容或共享分支。
- 若实际测试权限不满足这些边界，先完成可独立的本地验证，再明确暂停需要外部权限的项目，不能用 mock 替代并宣布总体通过。

## 整体验收矩阵

以下是整体完成判据，不代替各子 Spec 的局部测试。

| 场景 | 必须看到的结果 |
| --- | --- |
| 新白名单话题，无 @ | main 自动分诊，保留来源；建票包含目标/验收要求/配置快照，而非直接无授权起 Worker |
| 非白名单、机器人、自发消息 | 信息与授权分开；不能授权新工作、变更范围或批准合并，不自激循环 |
| 单项目实现 | project 创建隔离主执行，使用指定 Flash/max；原生 helper 可委派、继续、回报，不被 Nexus 同名工具破坏 |
| 跨项目协调 | 临时 supervisor 正确关联项目工单及依赖，一边未完成不假释放，失败/取消不冒充依赖成功 |
| 三档提问与三档合并策略 | 按 01 矩阵路由、代答；main 自己的 ask 恒问人，human_required 不被 automatic 或超时覆盖 |
| Web/GitHub 正式答复 | 同一 askId，一处回答全局生效；另一处不能覆写，普通同意、模糊引用和 bot 出站不被当批准 |
| 分级配置修改 | 改全局不动已有票；改本票有记录，旧决定不越过当前更严格策略，无凭空自动答案 |
| 编排者 ask 未答 | 另一票仍可推进；新事件打断当前等待但保留原 ask，晚答准确续接原工作线 |
| 提醒和无反应等待 | 宿主按间隔提醒责任方，仍无处置/无法恢复再上级；已等人关联原问题，不新建重复卡/评论 |
| 人介入、暂停、打断 | 标明来源；普通进度不自动杀 Worker；人暂停不被评论/CI/答复解除；中断不等于撤销外部副作用 |
| 重启与投递故障 | 原会话/工作区/待办可核对续接，不重复建票、开 Worker、批准或盲发远端动作；恢复失败可见 |
| PR 新 head、CI 未通过、未合并关闭 | 旧批准不适用新代码；未满足仓库/验收条件不自动合并或标成功 |
| 有 PR 交付 | 合并 ask、验收依据与实际 merged 事实一致；只合并隔离 base，合并 ask 不再重复一次验收提问 |
| 无 PR 与外部已合并 | 调查成果可按要求验收；外部事实如实显示，缺有效决定须核验，不伪造批准或重复合并 |
| Web 管理体验 | 真实工单/图/信箱一致，ask 有近况，打开正确来源的既有侧聊，一处答复同步；无示例数据冒充运行 |
| 禁用/失联/空态/错误 | 保留历史、不自动转派或启用；错误不是空列表，后续恢复路径明确 |

## 验证入口与构建限制

遵守 [AGENTS](../../../AGENTS.md)及[测试规范](../testing.md)。常规校验入口为：

    pnpm run lint --fix
    pnpm run typecheck
    pnpm run test -- --run

单测门禁还应覆盖独立重复运行至少 5 次与乱序，且实际匹配 unit include；现有 passWithNoTests 的绿色不算领域测试证据。使用实际数据库、状态转换和边界结果，不测试源码字符串或复制实现推导期望。

当前 test:e2e 脚本会先执行 build。插件开发期间禁止擅自运行构建，因此不能直接以该脚本绕过保护规则；已有匹配当前变更的 dev/预构建产物时，可使用不带 build 的实际浏览器项目入口：

    pnpm exec vitest run --project e2e

执行前须证明产物对应本次变更，否则即使浏览器绿也不是当前代码证据。没有可用产物/监听时，先明确请求用户允许必要的构建或启动安排；授权未给之前不能替代验证、暗中构建或强行宣布完成。

Windows/Linux 的测试契约遵循仓库标准；当前宿主没有执行的系统写为未执行，不把单平台通过当作跨平台证明。Chromium/CLI/模型/凭据缺失不得静默 skip。

## 既有 GUI 的验收

当前用户 GUI 为 http://127.0.0.1:3081，独立 E2E 地址通过不证明此 URL 已更新。

- 核实实际加载的插件/版本与 watcher；只有满足宿主 HMR 条件时才承诺无需刷新。其他情况在允许的部署/产物更新后刷新现有页面验证。
- 不用单独 Vite 页面或新服务器代替 dsh web 的启动注入，不把另一端口的截图当作当前 GUI。
- 对真实用户环境的最终检查以只读为主；不将自动化测试账本/假工单写入真实用户库。若需要安装、重启或改变当前 profile，先明确权限与影响范围。
- 若 05 需要最小侧聊 API 接线，先本地验证后统一向相应上游提 PR，记录实际链接/状态；deep-view 不在此列。

## 证据、阻塞与完成报告

报告至少区分：已验证、已执行但未验证、未执行/需用户条件。保留变更版本、实际命令/退出码、被测模型设置、会话/工单/ask 关联、GitHub 隔离 PR/base、浏览器地址以及关键断言结果。不能只放截图、lint 通过或一段模型自报完成。

每个剩余阻塞明确缺什么、影响哪项验收、下一步需要谁；例如模型凭据、GitHub 写权限、构建许可或部署接线。存在阻塞不强制收窄目标或将总纲标完成。

退出测试只清理本 run 的进程和资源，不能停止用户现有服务。任何必须长期保留的服务/临时资源须报告，不能遗留未收集的后台任务。

本目录的批准只授权后续按 /exec 实现；文档审查通过、现有空测试套件通过，都不是一期功能已经实现的证据。
